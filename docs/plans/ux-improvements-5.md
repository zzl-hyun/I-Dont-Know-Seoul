## 항목 2: 목적지 없을 때 등급색 + 통근 40분 복귀

> **아래 "목적지 없을 때 등급색 표시"(2a) 부분은 되돌려졌다** — 위 상태
> 블록 참고. 이 절의 설계 기록은 그 당시 판단 근거로 남겨 두지만, 현재
> 코드는 목적지가 없으면 다시 전 지역 회색이다. **40분 기본값(2b)만 유효.**

사용자 결정 덕에 **자동 조정(목적지 0→1 감지) 로직이 통째로 불필요**해졌다.
`App.tsx`에 그런 effect가 없어 새로 만들어야 했는데 그럴 필요가 없다.

- `constants.ts:108` `DEFAULT_MAX_COMMUTE_MIN` **90 → 40**
- **`App.tsx` `views` useMemo(`:270-303`)에서 처리하는 게 핵심.** 목적지가 없을 때
  `inTime`을 `true`로 두면 나머지가 자연히 따라온다:
  - `reachable = inTime && inBudget` → 목적지 없으면 **예산 필터만** 적용(합리적)
  - `reason`(`:288-300`)이 `reachable`일 때만 `summarize`를 부르므로 툴팁 문구도 자동 해결
  - `overBudget: inTime && !inBudget` 도 그대로 맞는다
- `MapView.tsx:630`의 `hasDestination ? ... : false` 강제 false를 제거해
  App이 계산한 `reachable`을 그대로 쓰게 한다
- `tooltipHtml`(`:885-890`)의 `!hasDestination` 조기 반환을 없앤다 — 아래 정상
  경로가 이미 `if (min !== null)`로 통근 줄을 감싸고 있어(`:897`) 목적지가 없으면
  등급+요약만 자연스럽게 나온다. `hasDestination` prop이 불필요해지는지 확인해 정리
- **`shareUrl.test.ts`가 두 군데 깨진다**(설계 검증에서 추가로 발견, 실제 코드로 확인함):
  - `:59` `expect(s.maxCommute).toBe(90)` → `40`
  - `:66-71` `"기존 공유 링크가 max=40을 명시하면…"` 테스트가 **통째로 무의미해진다.**
    `encodeShareState`는 `maxCommute !== 기본값`일 때만 `max=`를 싣는데(`:65`),
    기본값이 40이 되면 `max=40`이 안 실려 `toContain("max=40")`이 실패한다.
    애초에 이 테스트는 기본값이 90이 됐을 때 옛 40 링크를 지키려고 만든 것이라
    전제가 사라진다 → **기본값이 아닌 값(예: 55)으로 바꿔** "명시된 URL 값은
    기본값과 무관하게 왕복된다"는 원래 의도만 살린다
- **주의**: 슬라이더 상한 90은 `App.tsx:45`의 로컬 `MAX_COMMUTE_MINUTES`로
  `constants.ts`를 import하지 않는 별개 값이다. 혼동 금지
- `App.tsx:917-925`의 목적지 없을 때 안내 문구가 **"통근 가능한 지역이 지도에
  나타납니다"** 인데, 이제 목적지 전에도 전 지역이 등급색으로 보이므로 사실과
  어긋난다. "목적지를 검색하면 통근 가능한 곳만 골라볼 수 있습니다" 류로 조정
- `hasDestination` prop이 완전히 죽는지 확인하고 **Props·구조분해·`stateRef`·
  App.tsx 전달부까지 한꺼번에** 제거한다. 일부만 지우면 미사용 변수 오류가 난다
- **`mapMode === "commute"` + 목적지 없음** 엣지케이스: `band`가 -1이라 전부
  회색이 된다. 조건 패널이 `destinations.length > 0`으로 게이트돼 있어
  (`App.tsx:617`) 정상 UI로는 도달 불가하고 **조작된 `?mode=commute` 링크로만**
  생긴다. `fillColorExpr`(MapLibre 표현식)을 건드리는 대신 **상태 레벨에서 봉쇄**한다
  — `decodeShareState`에서 목적지 0개인데 `mode=commute`면 `grade`로 되돌리고,
  `removeDestination`의 마지막 하나 제거 분기에 `setMapMode("grade")` 추가

**알려진 부작용 — 그대로 두기로 결정**: `picks`(`:306-322`)는 `!commute`면 빈
배열이라, 목적지 없이 "지도부터 볼게요"로 들어오면 지도는 전 지역 색인데 목록은
"통근권 0개 동" + "통근 한계 15분 늘리기"가 뜬다. 사용자가 세 선택지 중
**"지금 그대로 둔다"**를 골랐다 → `picks`·`TopPicks` 빈 상태는 **건드리지 않는다.**

## 항목 5: 검색 직후 인터랙션·시선 유도

**본 앱엔 모션이 사실상 없다.** `index.css`에 `@keyframes`가 **0개**이고
transition은 5개뿐(버튼 hover·바 width 같은 미시적인 것). 검색하면 지도 카메라만
움직이고(`easeTo`/`fitBounds` 700ms) 색·마커·목록은 전부 즉시 스냅해서 "일이
일어났다"는 느낌이 없다. 반면 랜딩(`Landing.css`)엔 `hero-in`·`mark-pulse`·
`scroll-cue`와 `prefers-reduced-motion` 처리까지 잘 갖춰져 있다 — 그 격차를 메운다.

사용자가 4개 후보 중 **2개를 선택**했다(카운트업·목록 stagger는 제외).

### 5a. 지도 색 페이드인 (저위험·고효과)

- `dong-fill` paint에 **`"fill-opacity-transition": { duration: 320 }`** 추가.
  색 자체도 부드럽게 하려면 `"fill-color-transition"`도 함께
- MapLibre **네이티브 transition 옵션**이라 표현식이 아니다 → CLAUDE.md의
  "case 안에 zoom interpolate 중첩 금지" 함정과 무관하고 리스크가 거의 없다
- feature-state가 바뀔 때마다 작동하므로 검색뿐 아니라 **슬라이더·유형 선택을
  바꿀 때도** 계속 부드러워진다(부수 이득)
- `dong-icon`의 `circle-opacity`에도 같은 transition을 주면 마커가 팝 하지 않고
  스르륵 뜬다 — 항목 3(minzoom)과 함께 자연스러워짐

### 5b. 목적지 마커 펄스(ripple)

- `SRC_DEST`(`:135`, `:248`)를 **공유하는 `dest-pulse` circle 레이어**를 새로 추가.
  위치는 **`dest-marker`(`:503`) 바로 아래** — `dest-marker`가 현재 마지막(최상단)
  레이어라 실선 마커가 자기 물결 위에 남아야 한다.
  CLAUDE.md의 레이어 순서 절에 새 레이어를 **반드시 반영**할 것
- 레이어 정의는 `installLayers()` 안에 둔다 — 테마 전환 시 자동 재설치됨
- 애니메이션은 `setPaintProperty`를 `requestAnimationFrame`으로 돌려
  `circle-radius`(8→28 정도)와 `circle-opacity`(0.45→0)를 함께 움직인다.
  **무한 반복하지 말고 3~4회만 돌고 멈춘다**(계속 뛰면 산만하다)
- 트리거는 **`MapView.tsx:667-694`의 기존 destinations effect**(deps
  `[destinations, styleEpoch]`)에 얹는다. 목적지가 실제로 바뀔 때만 돌아야 하므로
  이전 값을 `useRef`로 비교
- **정리(cleanup) 필수**: 목적지가 또 바뀌거나 언마운트될 때 `cancelAnimationFrame`.
  안 하면 rAF가 누적된다
- `matchMedia("(prefers-reduced-motion: reduce)")`면 펄스를 아예 건너뛰고
  정적 마커만 둔다(랜딩의 `CountUp`이 쓰는 것과 같은 판정)

## 검증

**공통**: `npm test` / `npm run typecheck` / `npm run build` / `git diff --check`.
`shareUrl.test.ts`는 항목 2에서 반드시 손봐야 하므로 통과 여부를 꼭 본다.

**주의**: `cf:dev`는 `dist/`의 미리 빌드된 자산을 서빙한다. 소스만 고치고
`npm run build` 없이 새로고침하면 반영 안 된다(이 세션에서 실제로 겪음).

**실제 브라우저 시나리오** (`npm run build && npm run cf:dev`):
1. **목적지 없이 진입** — 지도가 등급색으로 전 지역이 칠해지는가. 마커는 안 보이는가
   (줌 9.9). 툴팁에 등급·요약이 뜨는가("먼저 목적지를 정해주세요"가 아니라)
2. 조작된 링크 `?mode=commute`(목적지 없음)로 들어가도 **회색 화면에 갇히지
   않는가**(위 가드 확인). 참고로 조건 패널 자체가 `destinations.length > 0`에
   게이트돼 있어(`App.tsx:617`) "목적지 없이 예산 슬라이더 조작"은 정상 UI로는
   불가능하다 — URL로만 만들어지는 상태다
3. **목적지(문정역) 추가** — 통근 40분이 기본으로 걸려 108개 수준으로 좁혀지는가
4. 확대해 들어가면 마커가 나타나는가. 그 줌이 자연스러운가(값 최종 결정)
5. **추천 목록 항목에 호버** — 지도에서 해당 동이 강조되는가. 지도 위 동에 호버하면
   목록에서도 강조되는가. **호버 시 지도가 움직이지 않는가**(중요)
6. 동을 클릭했을 때 기존 동작(상세 탭 전환·경로 점선·easeTo)이 그대로인가
7. 상세 패널 가격 축이 짧아졌는가. 접힌 부분을 펼치면 4유형 수치가 다 나오는가.
   동을 바꾸면 접힘 상태가 초기화되는가
8. **테마 전환(어둡게/밝게)** 후에도 hover·선택 강조가 살아있는가 —
   `styleEpoch` 처리가 맞는지 확인하는 가장 확실한 방법
9. **검색 시 펄스가 3~4회만 돌고 멈추는가.** 목적지를 연달아 바꿔도 이전 펄스가
   남아 겹치지 않는가(rAF cleanup 확인). 색이 스냅하지 않고 부드럽게 드는가
10. OS 설정에서 **동작 줄이기(reduce motion)**를 켜면 펄스가 사라지는가

## 리스크

- **MapLibre 표현식 함정**: `case` 안에 zoom interpolate 중첩 금지(항목 3).
  위반하면 레이어 추가 시 예외가 나고 **지도 초기화가 통째로 중단**되는데
  MapLibre는 `error` 이벤트로만 알려서 빈 화면이 된다
- **feature-state 소실**: 새 hover effect의 deps에 `styleEpoch`를 빠뜨리면
  테마 전환 후 강조가 안 걸린다. 검증 8번이 이걸 잡는다
- **항목 2 단독 배포 금지**: 항목 3 없이 나가면 첫 화면에 마커 547개가 쏟아진다
- 항목 2가 `reachable` 의미를 바꾸므로 `overBudget`·툴팁·마커 투명도가 연쇄로
  영향받는다. 목적지가 **있는** 경우의 동작이 기존과 완전히 같은지 반드시 확인
- **rAF 누수**(항목 5b): 목적지를 연달아 바꿀 때 이전 애니메이션을
  `cancelAnimationFrame` 하지 않으면 루프가 쌓여 마커가 떨린다
- 새 `dest-pulse` 레이어를 **CLAUDE.md의 레이어 순서 목록에 반영**해야 한다.
  안 적으면 다음 세션이 순서를 깨뜨린다(그 절이 존재하는 이유)
- **`MAP_THEME` 한쪽 테마만 채우는 실수**(항목 1의 `hoverOutline`) — 파일 헤더가
  이미 경고하는 패턴이다. dark/light 둘 다 채울 것
- **hover가 mousemove마다 리렌더를 유발**하지 않도록, 지도→목록 방향은 "코드가
  실제로 바뀔 때만 콜백" 가드를 넣는다. 547개 폴리곤을 스치듯 지날 때 문제가 된다
- **자동 테스트 사각지대**: `DongDetail.test.*`·`TopPicks.test.*`·`MapView.test.*`가
  **전부 없다.** 이번 5건은 대부분 이 세 파일에 몰려 있어 `npm test`가 회귀를 거의
  못 잡는다 — **브라우저 확인이 사실상 유일한 안전망**이다
