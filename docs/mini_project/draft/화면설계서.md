# 화면 설계서 — I Don't Know Seoul

> 개요.pdf의 B파트. `요구사항정의서.md` 뒤에 이어 붙인다.
> 기준 화면: 2026-09-15 `http://localhost:8787/` 실서비스를 Chrome 데스크톱(1440×900, 다크 테마)에서 직접 확인한 결과.
> Figma 와이어프레임: <https://www.figma.com/design/BkBbCbySeJIyypzw7k6xOW>

## 0. 설계 기준

- 이 문서는 **기획 초안이 아니라 현재 실행되는 SPA의 화면 상태**를 기준으로 한다.
- 조건 설정과 추천 목록은 별도 페이지가 아니라 메인 지도 오른쪽 사이드바의 `조건·추천` 탭에 함께 있다.
- 동 상세는 같은 사이드바의 `상세 정보` 탭으로 전환되어 열린다.
- 문의는 자체 저장 API가 아니라 Google Form을 패널 안에 임베드한다. 접수·보관은 외부 폼이 담당한다.
- 후기·로그인 화면(11장)은 현재 코드에 없다. 구현은 제출물이 아니므로 **설계 범위로 포함하되 미구현임을 표기**하고, 와이어프레임은 캡처 대신 박스 작도로 그린다.
- 화면 공통 데이터는 앱 진입 시 `GET /api/data`, 목적지 검색은 `GET /api/geocode?q={검색어}`로 가져온다. 통근·점수·필터·정렬은 브라우저에서 계산한다.
- 모든 화면은 REQ-NFN-005(Chrome·Edge·Safari 최신 2개 버전, 모바일 브라우저)를 공통으로 고려한다.

## 2. 사용자 흐름

```text
SCR-HOME-001
  ├─ 목적지 검색 ─▶ 검색 후보 선택 ─▶ SCR-REC-001
  └─ 목적지 없이 지도부터 ─────────▶ SCR-MAIN-001

SCR-MAIN-001 / SCR-REC-001
  ├─ 목적지 검색·추가(최대 3곳) ─▶ 지도·추천 즉시 갱신
  ├─ 통근·월세·주택유형·가중치 조정 ─▶ 지도·추천 즉시 재계산
  ├─ 지도 동 또는 추천 항목 선택 ─▶ SCR-DONG-001
  ├─ 노선 펼치기 ─▶ SCR-LINE-001
  ├─ 결과 링크 복사 ─▶ 동일 조건 URL 복원
  └─ 문의 버튼 ─▶ SCR-INQ-001 ─▶ SCR-INQ-002

SCR-DONG-001 ─ 후기 보기 ─▶ SCR-RVW-001 (읽기는 로그인 없이)
  └─ 후기 남기기 / 도움돼요 ─▶ (세션 없음) SCR-AUTH-001
                                  └ 카카오·GitHub 인가 ─▶ 콜백 ─▶ SCR-RVW-002 ─▶ SCR-RVW-001 갱신
```

## 3. 공통 화면 구조

### 3-1. 데스크톱

```text
┌──────────────────────────── 지도 1fr ────────────────────────────┬── 사이드바 380px ──┐
│ [밝게] [✓ 지하철 노선도] [노선 ▸]                    [+][-]      │ 브랜드·소개·언어     │
│                                                                  │ 목적지 검색/목록      │
│ 동 등급 폴리곤 + 지하철 노선 + 목적지/선택 동 표시              │ [상세 정보][조건·추천]│
│                                                                  │ 탭별 스크롤 콘텐츠    │
│ [지도 출처·저작권]                                               │ 데이터 기준·주의문구  │
└──────────────────────────────────────────────────────────────────┴─────────────────────┘
                                                                                [문의]
```

- 전체 높이 100%, 지도와 사이드바가 동시에 고정된다.
- 사이드바는 독립 세로 스크롤이며 탭은 상단 고정이다.
- 다크 테마 기본색: 배경 `#16181d`, 패널 `#1e2128`, 보조 패널 `#262a33`, 강조 `#4d8bf5`.
- 등급색: Best `#2e9e5b`, Normal `#e0a52b`, Bad `#c2504a`.
- 실제 제품 폰트는 Pretendard이며, Figma에서는 사용 가능 폰트 제약으로 Noto Sans KR을 대체 사용한다.

### 3-2. 모바일·태블릿

- 880px 이하에서는 `지도 45% / 사이드바 55%`의 상하 구조로 전환한다.
- 지도 공간을 확보하기 위해 노선별 펼침 필터는 숨기고 지하철 노선도 체크만 유지한다.
- 520px 이하 문의 패널은 좌우 12px 여백을 둔 전체 폭이며, 폼 화면은 뷰포트 높이에서 92px을 뺀 높이를 사용한다.
- 사이드바 탭, 검색, 결과 목록은 세로 스크롤로 접근한다.

## 5. SCR-MAIN-001 메인 지도 · 목적지 없음

**① 기본 정보** — 메인 지도 빈 상태 · 메인 > 시작 · v1.1 · REQ-FUNC-002, 004, 005, 010

**② 와이어프레임**

```text
┌───────────────────────────────┬──────────────────────┐
│ [밝게] [✓ 지하철] [노선 ▸]    │ I Don't Know Seoul   │
│                               │ 설명 / 언어 전환      │
│         수도권 지도           │ [ 목적지 검색      ] │
│       지하철 노선·역 표시     │                      │
│                               │ 먼저 목적지를 정해주세요.│
│                               │ 회사나 학교를 검색하면 │
│                               │ 통근 가능한 동네를 계산│
│                    [+][-]     │                      │
│ [출처]                        │ 데이터 기준 / 주의문구 │
└───────────────────────────────┴──────────────────────┘
```

**③ 상태와 예외**

- 목적지 0곳: 동 등급 추천을 만들지 않고 검색 안내를 표시한다.
- 검색어 2자 미만: 네트워크 요청 없이 후보를 비운다.
- 검색 결과 없음: 검색창 아래에 결과 없음 안내를 표시한다.
- `/api/data` 실패: 전체 화면 로딩/오류 상태에서 재시도를 안내한다.
- 서비스 범위 밖 장소는 추천 계산 입력으로 확정하지 않는다.

**③ 인터랙션 및 로직**

| UI 요소 | 동작 | 처리 방식 |
|---|---|---|
| 목적지 목록 | 최대 3곳 추가·개별 삭제, 지도 역 클릭으로도 추가 | 검색만 `/api/geocode`, 상태는 클라이언트 |
| 통근 상한 | 기본 40분, 통근권과 추천 목록 갱신 | 브라우저 계산 |
| 월세 상한 | 제한 없음 또는 상한값 적용 | 브라우저 필터 |
| 주택유형 | 단독·다가구, 연립·다세대, 오피스텔, 아파트 복수 선택 | 사전계산 월세 조합 선택 |

| 가중치 | 치안 40, 가격 35, 생활편의 25 기본 | 합계 100으로 재조정 후 즉시 재정렬 |
| 지도 색 기준 | 등급 / 통근시간 전환 | 폴리곤 색상 레이어 교체 |
| 추천 목록 | 상위 10개 행정동, 등급·자치구·통근시간 표시 | hover 시 지도 강조, 클릭 시 SCR-DONG-001 |
| 링크 복사 | 목적지·조건·선택을 URL 쿼리에 직렬화 | Clipboard API, 재접속 시 복원 |

**④ 예외 처리** — 조건을 만족하는 동이 없으면 필터 완화 안내를 표시한다. 목적지를 모두 삭제하면 SCR-MAIN-001 빈 상태로 돌아간다. 통근시간은 실시간 교통이 아닌 정적 지하철·버스 모델 추정치임을 하단에 고지한다.

## 7. SCR-DONG-001 동 상세

**① 기본 정보** — 동 상세 상태 · 메인 > 상세 정보 탭 · v1.1 · REQ-FUNC-007, 008, 009

**② 와이어프레임**

```text
┌──────────────────────────────────────┬────────────────────────────┐
│ 선택 동 흰색 외곽선                  │ [상세 정보][조건·추천]     │
│ 선택 동 → 목적지 파란 점선 경로      │ 용인시 수지구 풍덕천2동 ●Best│
│                                      │ 수도권 547개 동 중 2위     │
│                                      │ 한 줄 추천 근거             │
│                                      │ 종합 점수        67.2 /100  │
│                                      │ 치안 86  ━━━━━━━━━━━        │
│                                      │ 가격 65  ━━━━━━━━           │
│                                      │ 생활편의 43 ━━━━━           │
│                                      │ [▾ 계산 근거 전체 보기]     │
│                                      │ 원지표·백분위·가중치·수식   │
│                                      │ 통근 경로 38분 / 환승 없음  │
│                                      │ 도보 12 → 대기 3 → 지하철 23│
└──────────────────────────────────────┴────────────────────────────┘
```

**③ 정보 우선순위**

1. 지역명·등급·전체 순위와 한 줄 요약
2. 종합 점수와 치안·가격·생활편의 축 점수
3. `계산 근거 전체 보기`: 원지표 → 중앙값 비교 → 백분위 점수 → 가중치 → 종합식 → 통근 페널티 Φ(t)
4. 목적지별 총 통근시간·환승 횟수·도보/대기/승차 구간
5. 데이터 기준 시점·모델 한계·미수집 지표

**④ 지도 연동** — 선택 동을 흰색 외곽선으로 강조하고 지도 중심을 이동한다. 대표 생활권에서 목적지까지 점선 경로를 표시하며, 거주 좌표 보호를 위해 거주지에서 첫 역·정류장까지의 상세 선은 생략한다.

**⑤ 후기 진입 (설계 범위, 미구현)** — 상세 탭 맨 아래에 `이 동네 실거주 후기 N건 ▸` 버튼을 둔다. 클릭 시 SCR-RVW-001로 전환되며, 읽기에는 로그인이 필요 없다(REQ-FUNC-012).

```text
└────────────────────────────┘
```

- 지하철 노선도 전체 표시를 체크박스로 켜고 끈다.
- 펼침 패널에서 노선별 버튼을 눌러 개별 노선을 숨기거나 다시 표시한다.
- 880px 이하에서는 공간 확보를 위해 노선별 패널을 숨긴다.

## 11. 설계 범위 화면 (미구현)

> 아래 세 화면은 2026-09-15 기준 코드에 없다. 실습안내가 "구현(서버·화면 코딩)은 제출물이 아니다"라고 정하고 있어, 이번 설계 범위로 포함하되 미구현임을 표기한다.
> 와이어프레임은 실행 화면 캡처 대신 박스 작도로 그린다. 요구사항 REQ-FUNC-011~015가 이 화면들에 대응한다.

### 11-1. SCR-AUTH-001 소셜 로그인

**① 기본 정보** — 로그인 오버레이 · 후기 쓰기 시도 시 노출 · v1.0 · REQ-FUNC-011

```text
                         ┌──────────────────────────────┐
                         │ 후기를 남기려면 로그인이 필요합니다 [×] │
                         │ 읽기는 로그인 없이 계속할 수 있어요 │
                         ├──────────────────────────────┤
                         │ ① [  카카오로 계속하기  ]      │
                         │ ② [  GitHub로 계속하기  ]      │
                         ├──────────────────────────────┤
                         │ 닉네임 외의 정보는 저장하지 않습니다 │
                         └──────────────────────────────┘
```

- ①② 클릭 시 제공자 인가 화면으로 이동하고, 콜백에서 세션을 발급한 뒤 **직전에 하려던 동작(후기 작성·도움돼요)을 이어서 수행**한다.
- 별도 가입 화면은 없다. 최초 로그인 시 제공자 닉네임을 그대로 쓰고, 이미 쓰는 닉네임이면 뒤에 숫자를 붙인다.
- 제공자 토큰은 서버에만 두고 응답에 포함하지 않는다(REQ-NFN-003). 이메일·프로필 사진은 저장하지 않는다(REQ-NFN-004).

| 상태 | 화면 처리 | 오류 코드 |
|---|---|---|
| 정상 | 콜백 성공 → 패널 닫고 직전 동작 재개 | 200 |
| 잘못된 입력 | 인가 코드 누락·만료 → `로그인에 실패했습니다. 다시 시도해 주세요.` | 400 |
| 권한 없음 | 세션 없이 쓰기 API 호출 → 이 패널 노출 | 401 |
| 로딩 | 콜백 처리 중 스피너, 버튼 중복 클릭 차단 | — |
| 서버 오류 | 제공자 응답 실패 → `잠시 후 다시 시도하세요.` | 500 |

**호출 API** — `GET /api/auth/{provider}`, `GET /api/auth/{provider}/callback`, `POST /api/auth/logout`, `GET /api/auth/me`

### 11-2. SCR-RVW-001 동 후기 목록

**① 기본 정보** — 동 상세 하단 영역 · 메인 > 상세 정보 > 후기 · v1.0 · REQ-FUNC-012, 015

```text
┌────────────────────────────────────────────┐
│ 이 동네 실거주 후기 12건                    │
│ [내 목적지 관련순 ▾] 최신순 · 도움순        │
├────────────────────────────────────────────┤
│ 닉네임 · 거주 1년 4개월                     │
│ 판교역까지 38분 (체감 45분)                 │
│ 치안 ★★★★☆ 가격 ★★★☆☆ 편의 ★★★★☆        │
│ "언덕이 심해서 겨울엔 버스를 타게 됩니다…"  │
│ [👍 도움돼요 7]                    [신고 없음]│
├────────────────────────────────────────────┤
│ … 20건 단위 페이징                          │
├────────────────────────────────────────────┤
│           [ + 후기 남기기 ]                 │
└────────────────────────────────────────────┘
```

- 읽기는 로그인 없이 가능하다. 기본 정렬은 **내 목적지 관련순** — 지금 설정한 목적지와 후기 작성자의 통근 목적지가 가까운 순이다. 목적지를 설정하지 않았으면 최신순으로 내린다.
- `도움돼요`와 `후기 남기기`는 세션이 없으면 SCR-AUTH-001을 띄우고, 로그인 후 원래 동작을 이어서 수행한다.
- 이미 후기를 쓴 동이면 `후기 남기기`가 `내 후기 수정`으로 바뀐다.

| 상태 | 화면 처리 | 오류 코드 |
|---|---|---|
| 정상 | 목록·정렬 표시 | 200 |
| 권한 없음 | 미로그인 상태의 쓰기 시도 | 401 |
| 없는 대상 | 삭제된 후기에 반응 → `삭제된 후기입니다.` | 404 |
| 충돌 | 도움돼요 중복 → 버튼 상태만 동기화 | 409 |
| 빈 화면 | 후기 0건 → `아직 후기가 없습니다. 첫 후기를 남겨 주세요.` | — |
| 서버 오류 | 조회 실패 → `잠시 후 다시 시도하세요.` | 500 |

**호출 API** — `GET /api/regions/{code}/reviews`, `POST`/`DELETE /api/reviews/{id}/helpful`

### 11-3. SCR-RVW-002 후기 작성·수정

**① 기본 정보** — 후기 작성 모달 · 후기 목록 > 작성 · v1.0 · REQ-FUNC-013, 014

```text
                ┌────────────────────────────────┐
                │ 풍덕천2동 후기 남기기       [×] │
                ├────────────────────────────────┤
                │ ① 거주 기간   [ 1년 4개월  ▾ ] │
                │ ② 통근 목적지 [ 판교역     ▾ ] │
                │ ③ 체감 통근   [ 45 ] 분        │
                │ ④ 치안 ★★★★☆ 가격 ★★★☆☆     │
                │    생활편의 ★★★★☆             │
                │ ⑤ ┌──────────────────────────┐ │
                │    │ 20자 이상 입력하세요…    │ │
                │    └──────────────────────────┘ │
                │        [삭제]        [저장]     │
                └────────────────────────────────┘
```

- ②는 지금 설정한 목적지 중에서 고르거나 직접 검색한다. 이 값이 후기 목록의 **관련순 정렬 기준**이 된다.
- 한 사용자는 한 동에 후기 1건만 남긴다. 이미 있으면 같은 모달이 수정 모드로 열리고 `삭제`가 활성화된다.
- 저장하면 SCR-RVW-001 목록 최상단으로 반영된다.

| 상태 | 화면 처리 | 오류 코드 |
|---|---|---|
| 정상 | 신규 저장 201 / 수정 저장 200 → 목록 갱신 | 200·201 |
| 잘못된 입력 | 본문 20자 미만, 평점 미선택, 거주 기간 범위 밖 | 400 |
| 권한 없음 | 세션 만료 상태로 저장 시도 | 401 |
| 역할 다름 | 타인이 쓴 후기를 수정·삭제 시도 | 403 |
| 없는 대상 | 이미 삭제된 후기 수정 | 404 |
| 충돌 | 같은 동에 두 번째 후기 작성 → `이미 이 동네 후기를 남기셨습니다. 수정하시겠어요?` | 409 |
| 서버 오류 | 저장 실패 → `잠시 후 다시 시도하세요.` | 500 |

**호출 API** — `POST /api/regions/{code}/reviews`, `PATCH /api/reviews/{id}`, `DELETE /api/reviews/{id}`, `GET /api/places`

## 12. 실제 구현 API·상태 매핑

| 기능 | 실제 호출/처리 | 화면 |
|---|---|---|
| 데이터 번들 로드 | `GET /api/data` | MAIN, REC, DONG, LINE |
| 목적지 검색 | `GET /api/geocode?q={검색어}` | HOME, MAIN, REC |
| 점수·통근·추천·필터 | 클라이언트 계산 | REC, DONG |
| 상태 공유 | URL 쿼리 생성·복원, Clipboard API | REC |
| 문의 | 외부 Google Form iframe / 새 탭 링크 | INQ-001, INQ-002 |

현재 Worker는 `GET /api/data`·`GET /api/geocode` 두 엔드포인트만 제공하고 나머지는 브라우저에서 계산한다.
API 명세서(`..._API.yml`)는 이 구조를 서버 기반으로 정규화한 설계이며, 화면-엔드포인트 대응은 다음과 같다.

| 설계 엔드포인트 | 현재 구현 | 화면 |
|---|---|---|
| `GET /api/regions`, `GET /api/regions/{code}` | `GET /api/data` 번들 + 클라이언트 계산 | MAIN, REC, DONG |
| `GET /api/regions/{code}/commute` | 클라이언트 Dijkstra | DONG |
| `GET /api/places` | `GET /api/geocode` | HOME, MAIN, REC |
| `GET /api/subway-network` | `GET /api/data` 번들에 포함 | LINE |
| `/api/auth/*`, `/api/regions/{code}/reviews`, `/api/reviews/*` | 미구현 (설계 범위) | AUTH, RVW |
