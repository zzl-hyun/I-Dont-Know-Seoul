# 화면 설계서 — I Don't Know Seoul

> 개요.pdf의 B파트. `요구사항정의서.md` 뒤에 이어 붙인다.
> 기준 화면: 2026-09-15 `http://localhost:8787/` 실서비스를 Chrome 데스크톱(1440×900, 다크 테마)에서 직접 확인한 결과.
> Figma 와이어프레임: <https://www.figma.com/design/BkBbCbySeJIyypzw7k6xOW>

## 0. 설계 기준

- **화면 ID와 기능 범위는 요구사항정의서 6장 추적성 표를 따른다.** 화면 구성은 현재 실행되는 SPA를 기준으로 기술한다.
- `SCR-WGHT-001`(조건 설정)과 `SCR-PICK-001`(추천 목록)은 실제 화면에서 **메인 지도 오른쪽 사이드바 `조건·추천` 탭의 위·아래 영역**이다. 요구사항 단위로 분리해 기술하되 같은 탭에 있다는 점을 각 절에 명시한다.
- 동 상세는 같은 사이드바의 `상세 정보` 탭으로 전환되어 열린다.
- 지하철 노선 필터는 별도 화면이 아니라 `SCR-MAIN-001` 지도 위 오버레이다(REQ-FUNC-005).
- 후기·로그인 화면(10장)은 현재 코드에 없다. 구현은 제출물이 아니므로 **설계 범위로 포함하되 미구현임을 표기**하고, 와이어프레임은 캡처 대신 박스 작도로 그린다.
- 문의는 설계상 자체 접수(`POST /api/inquiries`)이며, 현재 구현은 Google Form을 패널에 임베드한 임시 운영이다(11장 대조표 참고).
- 화면 공통 데이터는 앱 진입 시 `GET /api/data`, 목적지 검색은 `GET /api/geocode?q={검색어}`로 가져온다. 통근·점수·필터·정렬은 브라우저에서 계산한다.
- 모든 화면은 REQ-NFN-005(Chrome·Edge·Safari 최신 2개 버전)를 공통으로 고려한다. **대상은 데스크톱 브라우저이며 모바일 화면은 이번 설계 범위가 아니다.**

## 2. 사용자 흐름

```text
SCR-HOME-001
  ├─ 목적지 검색 ─▶ 검색 후보 선택 ─▶ SCR-MAIN-001 (결과 상태)
  └─ 목적지 없이 지도부터 ─────────▶ SCR-MAIN-001 (빈 상태)

SCR-MAIN-001
  ├─ 목적지 검색·추가(최대 3곳) ─▶ 지도·추천 즉시 갱신
  ├─ 노선 필터 펼치기 ─▶ 노선별 표시·숨김
  ├─ 결과 링크 복사 ─▶ 동일 조건 URL 복원
  ├─ 사이드바 `조건·추천` 탭 ─▶ SCR-WGHT-001 ─▶ SCR-PICK-001
  ├─ 지도 동 또는 추천 항목 선택 ─▶ SCR-DONG-001
  └─ 문의 버튼 ─▶ SCR-INQ-001

SCR-DONG-001 ─ 후기 보기 ─▶ SCR-RVW-001 (읽기는 로그인 없이)
  └─ 후기 남기기 / 도움돼요 ─▶ (세션 없음) SCR-AUTH-001
                                  └ 카카오·GitHub 인가 ─▶ 콜백 ─▶ SCR-RVW-002 ─▶ SCR-RVW-001 갱신
```

## 3. 공통 화면 구조 (데스크톱 전용)

```text
┌──────────────────────────── 지도 1fr ────────────────────────────┬── 사이드바 380px ──┐
│ [밝게] [✓ 지하철 노선도] [노선 ▸]                    [+][-]      │ 브랜드·소개·언어     │
│                                                                  │ 목적지 검색/목록      │
│ 동 등급 폴리곤 + 지하철 노선 + 목적지/선택 동 표시              │ [상세 정보][조건·추천]│
│                                                                  │ 탭별 스크롤 콘텐츠    │
│ [지도 출처·저작권]                                               │ 데이터 기준·주의문구  │
└──────────────────────────────────────────────────────────────────┴─────────────────────┘
                                                                                [문의]
```

- 전체 높이 100%, 지도와 사이드바가 동시에 고정된다.
- 사이드바는 독립 세로 스크롤이며 탭은 상단 고정이다. `조건·추천` 탭 안에서 위가 SCR-WGHT-001, 아래가 SCR-PICK-001이다.
- 다크 테마 기본색: 배경 `#16181d`, 패널 `#1e2128`, 보조 패널 `#262a33`, 강조 `#4d8bf5`.
- 등급색: Best `#2e9e5b`, Normal `#e0a52b`, Bad `#c2504a`.
- 실제 제품 폰트는 Pretendard이며, Figma에서는 사용 가능 폰트 제약으로 Noto Sans KR을 대체 사용한다.

## 11. 설계 ↔ 현재 구현 대조

현재 Worker는 `GET /api/data`·`GET /api/geocode` 두 엔드포인트만 제공하고 점수·통근·추천·필터는 브라우저에서 계산한다.
API 명세서(`..._API.yml`)는 이 구조를 서버 기반으로 정규화한 설계이며, 대응은 다음과 같다.

| 설계 엔드포인트 | 현재 구현 | 화면 |
|---|---|---|
| `GET /api/regions`, `GET /api/regions/{code}` | `GET /api/data` 번들 + 클라이언트 계산 | MAIN, WGHT, PICK, DONG |
| `GET /api/regions/{code}/commute` | 클라이언트 Dijkstra | DONG |
| `GET /api/places` | `GET /api/geocode` | HOME, MAIN |
| `GET /api/subway-network` | `GET /api/data` 번들에 포함 | MAIN |
| `POST /api/inquiries` | 외부 Google Form iframe / 새 탭 링크 | INQ |
| `/api/auth/*`, `/api/regions/{code}/reviews`, `/api/reviews/*` | 미구현 (설계 범위) | AUTH, RVW |

| 상태 처리 | 실제 방식 | 화면 |
|---|---|---|
| 조건·가중치 변경 | 브라우저 재계산 후 즉시 재정렬 | WGHT, PICK |
| 상태 공유 | URL 쿼리 생성·복원, Clipboard API | MAIN |

## 12. 제출용 캡처 체크리스트

- [ ] SCR-HOME-001: 랜딩 히어로 전체(검색창 포함)
- [ ] SCR-MAIN-001: 목적지 없는 빈 상태 1장 + 목적지 설정 결과 상태 1장 + 노선 펼침 1장
- [ ] SCR-WGHT-001: 조건·추천 탭 상단(통근·월세·주택유형·가중치)
- [ ] SCR-PICK-001: 조건·추천 탭 하단(추천 목록)
- [ ] SCR-DONG-001: 추천 동 선택 + 지도 경로 + 상세 탭
- [ ] SCR-INQ-001: 문의 유형 3개 + 폼 화면
- [ ] SCR-AUTH-001: 박스 작도 (캡처 아님)
- [ ] SCR-RVW-001: 박스 작도 (캡처 아님)
- [ ] SCR-RVW-002: 박스 작도 (캡처 아님)

각 캡처에는 화면 번호를 덧씌우고 PDF 안에 이미지로 삽입한다. 외부 링크만 제출하지 않는다.
