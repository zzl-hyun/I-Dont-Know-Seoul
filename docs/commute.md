# 통근시간을 어떻게 계산하는가

← [README](../README.md)

이 서비스는 사용자가 목적지를 고를 때 외부 길찾기 API를 호출하지 않습니다.
지하철·버스·거주인구 데이터를 미리 정적 번들로 만들고, 브라우저에서 계산합니다.

---

## 런타임 외부 길찾기 API 호출은 0회입니다

목적지 하나당 **547개 동의 통근시간**이 필요합니다. 일반 길찾기 API를 동마다
호출하면 무료 한도로는 공개 서비스를 운영하기 어렵고, 같은 링크도 조회 시각에
따라 다른 결과가 됩니다.

대신 지하철 그래프와 첫·마지막 버스 접근망을 미리 만듭니다.

```text
목적지 좌표
  → 역별 목적지 접근(15분 이내 도보, 초과 시 같은 방향 직행 버스 검토)
  → 다중 출발점 Dijkstra (지하철 그래프)
  → 100m 분포를 동별 최대 24개로 집약한 대표 생활권에서 최적 승차역 선택
  → 동별 인구 가중 중앙 통근시간
```

목적지 쪽 Dijkstra는 한 번만 돌리고, 선택한 동의 상세 경로만 `prev` 배열로
되짚습니다. 슬라이더를 움직여도 네트워크 왕복이 없습니다.

---

## 동 중심점이 아니라 100m 거주인구 분포를 씁니다

양재1동처럼 주거지와 산지가 한 행정동에 함께 있으면 폴리곤 중심점 하나가 실제
주민을 대표하지 못합니다. 그래서 국가데이터처 SGIS 2024년 **100m 총인구 격자**
43,780개를 547개 동에 배정합니다.

원 셀에서 이용할 수 있는 역 접근 선택지를 미리 계산한 뒤, 공개 번들에는 동별
최대 24개 대표 생활권으로 집약합니다. 원 인구수는 동마다 합이 10,000인 가중치로
바꾸고 거주 좌표는 전혀 싣지 않습니다. 목적지가 정해지면 대표 생활권마다 가장
유리한 역을 고르고 누적 50%가 되는 통근시간을 동 대표값으로 씁니다. 그래서
산이나 행정경계 쪽의 단일 중심점에 끌려가지 않으면서 원 셀 데이터는 공개하지
않습니다.

버스 접근 프로필에는 노선 ID, 승·하차 순번, 승차 정류장까지의 도보시간도
보존합니다. 좌표 없이도 사전 계산과 같은 정방향 구간과 상세시간을 복원하기
위해서입니다. 상세 목록에는 첫 도보시간도 표시하지만, 공개 좌표가 없으므로
거주지에서 첫 역·정류장까지의 지도선은 그리지 않습니다.

집약 전후를 28개 목적지·15,316건으로 비교했을 때 평균 오차는 0.29분,
95%는 1분 이내, 최대는 2.75분이었습니다.

생활편의 축의 `최근접역 도보`도 같은 100m 분포의 인구 가중 중앙값입니다.

## 도보 15분을 넘으면 실제 버스 노선을 검토합니다

출발점↔역 또는 역↔목적지의 직접 도보가 15분을 넘을 때만 버스를 찾습니다.
양끝 450m 안에 정류장이 있고, **같은 노선의 운행 방향 순서**로 이어지며,
도보보다 최소 1분 빨라야 채택합니다. 환승 버스를 임의로 합성하지 않습니다.

```text
버스 접근시간
  = 승차 정류장까지 도보
  + 기대 대기시간
  + 노선 운행거리 / 15km/h
  + 정류장당 0.2분
  + 하차 정류장에서 도보
```

- 경기 노선의 기대 대기는 평일 첨두 배차간격의 절반을 우선 사용합니다.
- 서울 노선은 현재 API에 배차 필드가 없어 기본 15분의 절반을 씁니다.
- 기대 대기시간은 지나치게 작거나 커지지 않게 2~8분으로 제한합니다.
- 경기 운행거리는 2023 BMS가 현재 노선의 `노선ID+순번+정류장ID`와 정확히
  일치하는 구간만 사용합니다. 나머지와 서울은 정류장 직선거리×1.25입니다.

판교역→SK AX 기준 모델은 `602-1B` 노선을 찾아 도보 34분을 약 **17.8분**
(도보 2.9 + 대기 2 + 버스 10.3 + 도보 2.6)으로 바꿉니다. 사용자가 말한
평시 10분·혼잡 시 20분 사이의 보수적인 정적 추정치입니다.

## 노드는 "역"이 아니라 "(역, 노선)" 쌍입니다

강남역은 2호선 노드와 신분당선 노드로 나뉘고 그 사이를 환승 엣지가 잇습니다.
이렇게 해야 환승 비용이 경로 탐색에 자연스럽게 반영됩니다.

623개 역이 **758개 노드**가 되고, 그중 114개가 환승역입니다.

---

## 역간 소요시간 = 정차 페널티 + 거리 / 순항속도

노선별 표정속도 하나만 쓰면 역간거리가 짧은 노선과 긴 노선을 동시에 맞출 수
없습니다. 물리적으로 분해한 상수로 경전철부터 GTX까지 계산합니다.

검증 (`src/lib/commute.test.ts`):

| 구간 | 모델 | 실제 |
|---|---:|---:|
| 2호선 순환 일주 (43역 48.8km) | 87.5분 | 87분 |
| 1호선 서울역–인천 (27역) | 62분 | 약 60분 |
| 6호선 응암–봉화산 (38역) | 70분 | 약 75분 |
| 신분당 강남–정자 (6역) | 18분 | 약 16분 |
| 우이신설 전 구간 (13역) | 25분 | 약 24분 |

`src/lib/constants.ts`의 모델 상수를 바꾸면 반드시 `npm test`를 돌리세요.
버스 상수는 `scripts/lib/bus-access.mjs`에도 복제되어 있으며 테스트가 두 값을
대조합니다.

## 표시 구간의 합은 헤드라인과 일치합니다

도보, 버스 대기, 버스 승차, 지하철 대기, 지하철 승차, 환승을 모두 구간으로
드러냅니다. 구간 합이 총 통근시간과 같은지 회귀 테스트로 확인합니다.
구간별 화면 표시는 반올림하므로 눈에 보이는 정수 합에는 1분 정도 차이가 날 수
있고, 반올림해서 0분인 구간은 숨깁니다.

---

## 도보 보정 계수는 실측값입니다

`WALK_DETOUR_FACTOR`는 **1.4**입니다. `npm run data:calibrate-walk`의 OSM 보행망과
서울시 공식 보행망 교차검증 결과가 1.397 대 1.418이라 1.4를 유지했습니다.

역을 고를 때만 도보에 `WALK_SELECTION_WEIGHT`를 적용해 비슷한 총시간이면 덜
걷는 역을 선호합니다. 화면의 실제 시간에는 이 가중치를 넣지 않습니다.

## 한계

- 버스는 **첫·마지막 접근의 무환승 동일 노선**만 봅니다. 버스끼리 환승하거나
  지하철 대신 버스만 타는 전체 경로는 계산하지 않습니다.
- 실시간 위치·교통상황은 반영하지 않습니다. 특히 혼잡시간 버스는 더 오래 걸릴
  수 있습니다.
- 서울 노선 배차는 공개 API 필드 한계로 기본값을 사용합니다.
- 경기 BMS 스냅샷은 2023년 자료이며 현재 노선과 정확히 일치하는 구간만 씁니다.
- 지하철 역간 소요시간은 전 구간 추정치이고 급행을 반영하지 않습니다.
- 환승 도보시간은 상수이며 실제 1~10분 차이를 표현하지 못합니다.
- 지도 경로선은 정류장·역 좌표를 이은 선으로 실제 도로·선로 모양이 아닙니다.
