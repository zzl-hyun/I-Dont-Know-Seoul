# 지오비전·상권 데이터 조사 핸드오프

> Claude에게 전달하는 조사 기록입니다. 2026-08-11(KST) 기준으로 공식 웹페이지와 현재 저장소를 확인해 작성했습니다. 확인된 사실, 프로젝트 적용 권고, 아직 확인하지 못한 사항을 분리했습니다. API 응답 스키마나 이용 허가를 추측해서 적지 않습니다.

## 1. 결론

현재 제품에 필요한 것은 실시간 데이터가 아니라 서울 지역의 `상권 활력`과 `생활 편의`를 평가할 수 있는 정적·통계 데이터입니다.

- Puzzle 지도 화면은 크롤링 대상으로 사용하면 안 됩니다. Puzzle 이용약관은 콘텐츠의 수집·다운로드·색인·저장·캐시와 유사 서비스 제작을 금지하고 있습니다. 이 제한은 실시간 데이터에만 적용된다고 적혀 있지 않으므로, 과거·통계 화면을 수집하는 경우에도 안전하지 않습니다.
- 현재 프로젝트의 편의 지표는 OSM 기반 POI와 교통·도보 데이터로 계산되고 있습니다. Geovision이나 서울시 `골목상권분석정보`는 현재 사용 중인 데이터가 아닙니다.
- 정적인 상권 분석이 목적이면, 우선 서울시 공식 `골목상권분석정보`를 검토하는 것이 가장 직접적인 경로입니다. 점포 수·추정매출·유동인구·상권변화지표·집객시설 등을 제공하며 분기 단위 데이터입니다.
- SK Open API를 추가로 쓰려면 공식 API 상품을 통해서만 검토합니다. 앱 등록·서비스 활성화·인증키·저장/재배포 조건은 상품별로 확인해야 하며, 공개 요금표만으로 사용 권한 전체를 확정하면 안 됩니다.

## 2. 현재 저장소에서 확인한 데이터

확인 대상: [README.md](./README.md), [CLAUDE.md](./CLAUDE.md), [scripts/3-metrics.mjs](./scripts/3-metrics.mjs), [data/dist/metrics.json](./data/dist/metrics.json), [worker/index.ts](./worker/index.ts)

현재 프로젝트는 서울시 427개 행정동을 대상으로 안전·가격·편의 축을 계산하는 정적 데이터 파이프라인입니다.

현재 확인된 소스와 역할은 다음과 같습니다.

| 현재 소스 | 현재 역할 |
| --- | --- |
| OpenStreetMap/Overpass | 편의점·마트, 음식점, 의료, 유흥, 버스 정류장 등 POI 집계 |
| OSM 지하철 | 역 접근성과 도보 시간 계산 |
| 범죄 CSV | 안전 지표 |
| 교통사고 CSV | 안전 지표 |
| 국토부 실거래/임대 관련 데이터 | 가격 지표 |
| 구별 인구 CSV | 일부 안전 지표 정규화 |

저장소 전체에서 `골목상권`, `상권분석`, `서울시 상권`을 검색했지만 해당 서울시 상권분석 데이터나 Geovision 데이터 파일은 확인되지 않았습니다. 따라서 서울시 상권분석정보를 추가한다면 기존에 사용 중인 데이터가 아니라 새 데이터 소스입니다.

다만 의미상 겹치는 부분은 있습니다. 서울시 데이터의 점포·집객시설 정보와 기존 OSM POI는 모두 “무엇이 얼마나 있는가”를 설명할 수 있습니다. 두 값을 단순히 더하지 말고, 아래처럼 역할을 나누거나 하나를 기준 소스로 정해야 합니다.

- `편의도`: OSM POI 수, 의료·식음료·교통 접근성 등 생활 접근성
- `상권활력도`: 서울시 추정매출, 유동/상주인구, 점포 수, 상권변화지표 등 상업 활동
- `안전도`: 기존 범죄·사고 데이터
- `가격`: 기존 임대/실거래 데이터

## 3. 사용자가 제시한 Puzzle 지도 URL

검토한 URL:

```text
https://puzzle.geovision.co.kr/map?lat=37.36920220581427&lng=127.11057186126752&zoom=14&poiId=222&poiType=subway&overlayType=FP
```

### 판단: 크롤링하지 않음

[Puzzle 이용약관](https://puzzle.geovision.co.kr/terms)에서 다음 내용을 확인했습니다.

- 약관에서 허용한 범위를 넘는 이용은 SKT의 사전 요청·승인이 필요합니다.
- Puzzle 콘텐츠를 무단으로 복사할 수 없습니다.
- 웹사이트·앱에서 Puzzle 콘텐츠를 수집, 다운로드, 색인, 저장, 캐시하는 행위가 금지되어 있습니다.
- Puzzle 콘텐츠를 이용해 유사 서비스를 만들거나 콘텐츠를 재배포하는 것도 금지되어 있습니다.
- 웹/앱에 Puzzle 서비스를 직접 삽입하는 것은 일반적으로 허용되지 않고, 링크나 버튼으로 연결하는 방식이 안내되어 있습니다.
- 자체 웹/앱에서 데이터를 이용하려면 [SK Open API 상품 목록](https://openapi.sk.com/content/API)을 사용하고, 공개 API에 포함되지 않은 데이터는 `data-puzzle@sk.com`으로 문의하라고 안내합니다.

따라서 “실시간이 아니면 괜찮다”, “브라우저에서 보이는 데이터니까 가져와도 된다”, “개인/비상업 프로젝트니까 저장해도 된다”라고 결론 내리면 안 됩니다. 현재 확인된 약관만으로는 해당 지도 URL을 반복 요청해 데이터를 수집·저장·인덱싱하는 구현을 진행하지 않습니다.

## 4. 서울시 공식 대안: 골목상권분석정보

정적 상권·편의 정도가 목적이라면 다음 공식 자료가 우선 후보입니다.

- [서울시 우리마을가게 상권분석서비스 소개](https://golmok.seoul.go.kr/introduce.do)
- [서울 열린데이터광장 데이터 안내](https://data.seoul.go.kr/dataList/3/literacyView.do)

공식 소개 페이지에서 확인된 범위:

- 점포 수, 추정매출, 유동인구, 상주인구, 상권변화지표, 집객시설 등 상권 분석 항목을 제공합니다.
- 행정동·상권 단위의 조회와 순위 확인을 지원합니다.
- `골목상권분석정보`는 Excel/CSV/Open API/SHP 형태의 제공 방법이 안내되어 있습니다.
- 데이터는 2019년 이후 분기 단위로 제공된다고 안내되어 있습니다.
- 최신 분기 데이터는 분기 종료 후 약 두 달 뒤 갱신될 수 있다고 안내되어 있습니다. 따라서 실시간 데이터가 아닙니다.
- 소개 페이지에는 점포 정보, 카드 매출, 서울/KT 유동인구, 교통카드, 주민·직장인 인구 등 데이터별 출처가 구분되어 있습니다. 이 데이터는 SKT Geovision과 동일한 데이터셋이라고 간주하면 안 됩니다.

이 자료를 사용하면 현재 요구에 맞는 “이 지역의 상업 활동이 어느 정도인가”를 계산할 수 있습니다. 다만 실제 다운로드/API 페이지에서 필드명, 공간 키, 분기 값, 이용 조건을 확인한 뒤 파이프라인에 연결해야 합니다.

## 6. Free plan에 대한 안전한 해석

각 상품의 공개 가격 페이지에서 `API 그룹 | 요금제` 표와 `Free` 열에 `10건 / 월`이 표시되는 것을 확인했습니다. 예시는 다음과 같습니다.

- [장소 혼잡도 요금](https://openapi.sk.com/products/calc?menuSeq=263&svcSeq=56)
- [주거생활 요금](https://openapi.sk.com/products/calc?menuSeq=413&svcSeq=66)
- [지하철 요금](https://openapi.sk.com/products/calc?menuSeq=142&svcSeq=54)
- [음식점 요금](https://openapi.sk.com/products/calc?menuSeq=490&svcSeq=69)
- [학원 요금](https://openapi.sk.com/products/calc?menuSeq=456&svcSeq=70)
- [국내여행 요금](https://openapi.sk.com/products/calc?menuSeq=272&svcSeq=57)

가격 페이지에는 상품별 API 그룹이 따로 표시되고, 무료 한도 초과 시 자동 차단된다는 안내도 있습니다. 그러나 공개 표만으로 다음 사항은 확정할 수 없습니다.

- 10건/월이 API 그룹별인지, 상품 전체 또는 계정 전체 공유인지
- 동일 상품의 여러 그룹 한도가 서로 독립적인지
- 서비스 신청·승인·활성화가 필요한지
- 호출 결과를 저장·캐시·배포할 수 있는지
- 배치 조회나 대량 좌표 조회가 가능한지

따라서 Free plan의 실전 전략은 다음처럼 보수적으로 잡습니다.

1. 실시간 화면 요청마다 API를 호출하지 않고, 먼저 정적 소스인 서울시 상권분석정보로 기본 지표를 구성합니다.
2. SK API가 꼭 필요한 경우에는 후보 상품을 하나만 고르고, 가장 가치가 큰 통계 그룹의 테스트 호출부터 합니다.
3. 대시보드의 실제 잔여 한도와 상품별 이용 조건을 확인하기 전에는 “상품마다 월 10건을 각각 쓸 수 있다”고 설계하지 않습니다.
4. 배치·캐시·장기 보관·공개 배포를 허용된다고 가정하지 않습니다. 허용 여부를 확인한 뒤에만 서버 저장이나 정기 갱신을 설계합니다.
5. API 키는 브라우저 코드나 `VITE_*` 변수에 넣지 않고 서버/Worker 측 비밀값으로만 취급합니다. 이것은 현재 프로젝트의 보안 설계 권고이지, SK의 약관에서 확인한 문구는 아닙니다.

## 7. 프로젝트에 적용할 때의 권장 경계

### 1단계: 서울시 데이터로 상권 활력 지표 추가

새 데이터셋을 별도 raw/processed 경로로 관리하고, 행정동 키와 분기 기준을 현재 427개 행정동 데이터에 매핑합니다. 우선 검토할 후보 지표는 다음입니다.

- 점포 수 또는 점포 증감
- 추정매출 및 증감
- 유동인구·상주인구·직장인구
- 상권변화지표
- 집객시설 수

정규화와 가중치는 기존 제품 점수 계약을 임의로 바꾸지 말고, 먼저 별도의 `상권활력도` 후보 지표로 검증합니다.

### 2단계: 기존 OSM 편의도와 중복 점검

OSM은 지도상의 시설 접근성과 존재 여부에 강점이 있고, 서울시 상권분석정보는 행정동/상권 단위의 통계와 상업 활동에 강점이 있습니다. 같은 “음식점 수”처럼 보이는 필드는 수집 기준과 시점이 다를 수 있으므로, 두 값을 합산하지 말고 비교 리포트를 먼저 만듭니다.

### 3단계: SK API는 보조 데이터로 검증

서울시 데이터만으로 부족한 질문이 있을 때만 SK API를 검토합니다. 예를 들어 통계 방문자·유입력·연령 분포가 상권 활력을 보완하는지 확인할 수 있습니다. 그 경우에도 먼저 상품 약관과 대시보드에서 이용/보관 조건을 확인하고, 공식 API 호출만 사용합니다.

## 8. Claude가 구현 전에 확인해야 할 미확정 사항

다음은 공개 상품 설명만 보고 결정하면 안 되는 항목입니다.
