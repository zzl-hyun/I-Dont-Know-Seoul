# I Don't Know Seoul

**https://i-dont-know-seoul.cioud.workers.dev**

갓 상경해 자취방을 구할 때, 회사나 학교를 검색하면 **통근 가능한 서울 동네들이
평판 등급으로 칠해진 지도**를 보여줍니다.

- 서울 **427개 행정동**을 Best / Normal / Bad 로 등급화
- 목적지 기준 **통근시간**을 지하철 그래프로 직접 계산 (외부 길찾기 API 호출 0회)
- **치안 / 가격 / 생활편의** 가중치를 직접 조절 → 즉시 재계산
- 등급이 왜 그렇게 나왔는지 **계산 과정을 전부 공개**
- **목적지 여러 개** — "우리 둘 다 40분 이내인 동네" (최대 3곳)
- **예산 필터**로 월세 상한을 잘라내고, 지도를 등급/통근시간으로 전환
- **지하철 노선도** 오버레이 (623개 역, 21개 노선) — 노선별 on/off
- 찾은 결과를 **링크로 공유**, 다크/라이트 테마

---

## 이 지도를 어떻게 읽는가

**등급은 절대 평가가 아니라 서울 안에서의 상대 평가입니다.** 상위 30%가 Best,
하위 30%가 Bad입니다. "Bad"는 살 수 없는 동네라는 뜻이 아니라, 같은 조건에서
비교했을 때 서울 하위권이라는 뜻입니다.

세 축으로 봅니다.

| 축 | 무엇을 보는가 | 기본 가중치 |
|---|---|---|
| **치안** | 유흥업소 밀도, 5대범죄(자치구), 교통사고 다발지역 | 40% |
| **가격** | 환산월세 중앙값 (단독·다가구·오피스텔·소형아파트) | 35% |
| **생활편의** | 편의점·마트, 음식점, 병원·약국 밀도, 교통 접근성(역 도보 + 버스) | 25% |

가중치 슬라이더가 있는 이유는 **정답이 사람마다 다르기 때문**입니다. 월세가
제일 중요한 사람과 조용한 동네가 제일 중요한 사람에게 같은 순위를 강요할 근거가
없습니다. 슬라이더를 움직이면 등급, 추천 순서, 요약 문장이 전부 즉시 바뀝니다.

동을 클릭하면 **왜 그 등급인지**가 나옵니다. (목적지를 강남역으로 뒀을 때)

```
동작구 노량진1동                            ● Best
서울 427개 동 중 24위 · 상위 6%

"월세가 60만원으로 싸고 범죄는 적지만, 교통사고 다발지점이 많습니다."

31분                                        환승 1회
  8분  노들역까지 도보
  3분  승차 대기
 13분  9호선 7정거장 · 노들 → 신논현
  5분  신논현역 환승 · 9호선 → 신분당선
  1분  신분당선 1정거장 · 신논현 → 강남
  1분  목적지까지 도보

치안    ▓▓▓░░ 59                          ▸ 계산 과정
가격    ▓▓▓▓░ 77                          ▸ 계산 과정
생활편의 ▓▓▓▓░ 74                          ▸ 계산 과정
```

지도 좌상단의 **지하철 노선도** 토글로 노선을 켜고 끌 수 있습니다. 노선 색은
실제 노선색 그대로이고, 환승역은 다른 점으로 구분되며, 확대하면 역 이름이 나옵니다.
"노선" 범례에서 개별 노선을 끌 수도 있고, 노선에 커서를 올리면 몇 호선인지 뜹니다.
지도의 역을 클릭하면 바로 목적지가 됩니다.

### 목적지를 여러 개 둘 수 있습니다

커플이 각자 다른 회사에 다니거나 회사 + 학원처럼, **"둘 다 40분 이내인 동네"**를
찾는 건 흔한 니즈입니다. 목적지를 최대 3곳까지 더하면 **모두 만족하는 지역**만
남습니다.

판정은 가장 오래 걸리는 쪽 기준입니다. 평균이나 합을 쓰면 "한 명은 20분, 다른
한 명은 90분"인 동네가 통과해버립니다.

```
강남역만          → 통근권 138개 동
강남역 + 여의도역 → 통근권  73개 동
```

### 지도 색은 두 가지로 볼 수 있습니다

**등급**(초록–노랑–빨강)과 **통근시간**(파랑 농담) 중에 고릅니다. 통근시간 모드는
20·30·40·60분 밴드로 칠해 등시선처럼 보입니다. 두 모드의 색 계열을 다르게 둔
이유는, 같은 계열이면 "빨간 동네가 나쁜 건지 먼 건지" 구분이 안 되기 때문입니다.

### 찾은 결과는 링크가 됩니다

목적지·통근한계·가중치·예산·지도 모드가 전부 주소에 담깁니다. 링크를 받은 사람은
같은 화면을 그대로 봅니다. 서버에 아무것도 저장하지 않습니다.

## 등급은 어떻게 계산되는가

관악구 신림동을 예로 한 번 관통해 보겠습니다.

**1단계 — 원지표 수집**

```
유흥업소 0개/km²   월세 55만원   편의점 25.6개/km²
역까지 도보 6분    버스 정류장 31.5개/km²
```

**2단계 — 서울 427개 동 안에서 백분위로 환산**

```
유흥업소 0개/km² → 백분위 77.6
```

여기서 흔한 오해가 하나 생깁니다. **유흥업소가 0개인데 왜 100점이 아닌가?**
서울 동의 **45%가 0개**라서, 동점인 동들이 순위를 나눠 갖기 때문입니다.
설명이 없으면 계산이 틀린 것처럼 보이므로 화면에도 이 사실을 함께 적습니다.

백분위를 쓰는 이유는 강남 월세 같은 이상치 하나에 전체 분포가 끌려가지 않고,
단위가 다른 지표(개/km², 만원, 분)를 같은 축에서 섞을 수 있기 때문입니다.

**3단계 — 축 점수 (하위 지표의 가중합)**

```
생활편의 77.5 = 78.4×0.30 + 60.3×0.25 + 89.0×0.20 + 83.2×0.175 + 87.0×0.075
                편의점       음식점       병원         역도보       버스
```

교통(역 도보 + 버스)의 합은 0.25이고 그 안에서 **지하철 7 : 버스 3** 입니다.
서울에서 지하철이 정시성·속도 모두 우위인 데다, 무엇보다 이 앱의 통근시간 계산
자체가 지하철만 씁니다. 버스 정류장 밀도는 독립적인 교통 지표라기보다 "지하철이
안 닿는 동네의 보완재" 입니다.

**4단계 — 종합 점수 (사용자 가중치)**

```
75.2 = 77.6×0.40 + 70.9×0.35 + 77.5×0.25
       치안         가격         편의
```

**5단계 — 등급 컷**

서울 전체 분포에서 상위 30% 지점의 점수 이상이면 Best입니다. 가중치를 바꾸면
점수 분포가 통째로 이동하므로 이 컷도 함께 움직입니다.

## 빠른 시작

```bash
npm install

# 1) 행정동 경계 (전국 34MB → 서울만 추출)
curl -L "https://raw.githubusercontent.com/vuski/admdongkor/master/ver20260701/HangJeongDong_ver20260701.geojson" \
  -o data/raw/hangjeongdong_20260701.geojson
npm run data:boundaries

# 2) 지하철 그래프 (OpenStreetMap, 키 불필요)
npm run data:subway

# 3) 동별 원지표 (OSM POI는 키 불필요 — 아래 "API 키" 참고)
npm run data:metrics

# 4) 정규화 + 등급 + 앱 번들
npm run data:score

# 5) 실행
npm run cf:dev   # Worker + 정적자산 통합 → http://localhost:8787
npm test         # 통근·등급 설명·노선도·URL 공유 회귀 테스트 64개
```

`data/raw/` 는 캐시입니다. 다시 받으려면 해당 파일을 지우고 스크립트를 재실행하세요.

## 설계에서 가장 중요한 결정

### 통근시간을 외부 API 없이 계산합니다

목적지 하나당 427개 동의 통근시간이 필요합니다. 길찾기 API를 쓰면 요청당
427콜이라, ODsay 무료 티어(1,000콜/일)로는 **하루 2명**밖에 못 씁니다.

대신 **지하철 그래프를 직접 만들어 브라우저에서 Dijkstra를 돌립니다.**

```
목적지 좌표
  → 반경 1.5km 내 지하철역 + 도보시간
  → 다중 출발점 Dijkstra (758노드 / 1,822엣지, 1ms 미만)
  → 역별 최단 도달시간
  → 각 행정동: min(동중심→인근역 도보 + 그 역 도달시간)
```

외부 API 호출이 **0회**라 사용량 제한도 요금도 없고, 슬라이더를 드래그해도
네트워크 왕복 없이 즉시 반응합니다. 선택한 동의 경로는 Dijkstra의 `prev` 배열로
그때 되짚습니다 — 427개를 미리 만들면 대부분 버려집니다.

### 노드는 "역"이 아니라 "(역, 노선)" 쌍입니다

강남역은 2호선 노드와 신분당선 노드로 나뉘고 그 사이를 환승 엣지가 잇습니다.
이렇게 해야 환승 비용이 경로 탐색에 자연스럽게 반영됩니다. 623개 역이 758개
노드가 되고, 그중 114개가 환승역입니다.

### 역간 소요시간 = 정차 페널티 + 거리 / 순항속도

노선별 "표정속도"를 하나씩 찍는 방식은 역간거리가 짧은 노선(6호선)과 긴 노선
(GTX)을 동시에 맞출 수 없습니다. 표정속도 자체가 역간거리에 종속된 값이기
때문입니다. 물리적으로 분해하면 상수 두 개로 경전철부터 GTX까지 설명됩니다.

검증 (`src/lib/commute.test.ts`):

| 구간 | 모델 | 실제 |
|---|---|---|
| 2호선 순환 일주 (43역 48.8km) | 87.5분 | 87분 |
| 1호선 서울역–인천 (27역) | 62분 | 약 60분 |
| 6호선 응암–봉화산 (38역) | 70분 | 약 75분 |
| 신분당 강남–정자 (6역) | 18분 | 약 16분 |
| 우이신설 전 구간 (13역) | 25분 | 약 24분 |

화면에 나열하는 구간 시간의 합은 헤드라인 숫자와 **정확히 일치**합니다. 그래서
총 통근시간에만 들어 있던 최초 승차 대기(3분)도 구간으로 드러냈습니다.

### 점수는 백분위, 등급은 상대 컷

각 원지표를 서울 427개 동 내 **백분위(0~100)** 로 바꿉니다. 평균/표준편차나
min-max 정규화는 강남 월세 같은 이상치 하나에 전체 분포가 끌려갑니다.

축 점수를 백분위로 저장해두면 종합 점수는 클라이언트에서 **427회 곱셈**이면
되므로, 가중치 슬라이더를 사실상 공짜로 제공할 수 있습니다.

등급은 **서울 전체 분포 기준 상대 컷**(상위 30% / 중간 40% / 하위 30%)입니다.
절대 컷을 쓰면 가중치를 바꾸는 순간 분포가 통째로 이동해 대부분이 한 등급으로
몰립니다.

### 요약 문장은 가중치를 반영합니다

극단값 순으로만 지표를 고르면 신림동 요약이 *"병원·약국이 가깝고 역이 가깝고
편의점·마트가 많습니다"* 가 됩니다 — 자취방을 찾는데 월세가 빠집니다. 그래서
극단성에 **그 지표가 최종 점수에 기여하는 비중**을 곱해 우선순위를 정합니다.
슬라이더를 움직이면 문장도 따라 바뀌는데, 그게 맞는 동작입니다.

좋은 점만 나열하면 광고가 되고 나쁜 점만 나열하면 낙인이 되므로, 양쪽이 다
있으면 역접으로 섞습니다. Bad 등급이면 부정 요인을 앞에 둡니다.

### 왜 지하철 데이터를 OSM에서 받는가

국내 공개 데이터셋(서울교통공사 역간거리 등)은 1~8호선만 다루거나 수년째 갱신이
멈춰 있어서 **신림선(2022)·우이신설선(2017)·신분당선 연장이 빠집니다.**
그러면 관악구·강북구가 통째로 "역 없음"이 되어 자취 추천이 망가집니다.
OSM은 노선 릴레이션에 정차 순서가 들어있고 신설 노선이 즉시 반영됩니다.

### CCTV 밀도를 쓰지 않는 이유

원래 치안 축에 넣으려던 서울 열린데이터광장 "안심이 CCTV 연계 현황"(OA-20923)은
**2026-02-10 자로 폐기**됐습니다("안심주소에 IP 노출로 국정원 지적"). 현재 API는
ERROR-500 을 반환합니다.

대안으로 OSM `man_made=surveillance` 를 검토했으나 서울 875개로, 실제 공공 CCTV
약 8만대의 1% 수준입니다. 이걸 밀도 지표로 쓰면 지역 간 치안 차이가 아니라
지역 간 매핑 활동 차이를 재게 되므로 넣지 않았습니다.

CCTV 자리는 새 출처가 생기면 채울 수 있도록 비워뒀습니다 —
`scripts/3-metrics.mjs` 의 `counts.get(code).cctv` 를 채우고 `cctvOk` 를 켜면
됩니다. 대신 치안 축은 아래 두 지표로 보강했습니다.

### 5대범죄 — 왜 자치구 단위인가

경찰청 공개 범죄 통계(경찰청_범죄 발생 지역별 통계)는 **시/군/구 단위**까지만
제공됩니다. 더 세밀한 해상도(파출소·행정동 단위)는 공개 데이터로 없습니다 —
CCTV와 달리 데이터 자체가 없는 게 아니라 공개 범위의 한계입니다. 그래서 같은
자치구에 속한 동들은 `crimePer1k` 값이 전부 같습니다(월세의 법정동 해상도
한계와 같은 성격).

원본 통계는 39개 세부 범죄 유형(사기·기타범죄 포함)을 다 담고 있는데, 그대로
합치면 지능범죄(사기 등)가 폭력·절도보다 커져 "동네 체감 치안"과 무관한
신호가 됩니다. 표준 5대범죄 정의(살인·강도·강간강제추행·절도·폭력)를 따라
강력범죄·절도범죄·폭력범죄 세 대분류만 합산하고, 행안부 주민등록인구로
나눠 인구 1천명당 건수로 정규화합니다.

### 교통사고 다발지역 — 취약계층 지점만 포함

원본(전국교통사고다발지역표준데이터)에서 서울분을 내려받은 결과 실제로 담긴
유형은 스쿨존어린이·보행어린이·보행노인·자전거, 네 가지뿐이었습니다(차대차 등
다른 유형은 이 다운로드에 없었습니다). 좌표 단위 데이터라 427개 동 중
94.6%에 최소 1건이 배정되어, 자치구 단위인 5대범죄보다 해상도가 훨씬
좋습니다. 2012~2024년 누적 데이터라 여러 해 반복 지정된 지점은 그만큼
가중되는데, 이건 의도한 동작입니다 — 여러 해 계속 위험지점으로 지정됐다는
건 일시적 사고가 아니라 구조적으로 위험하다는 뜻이기 때문입니다.

### 법정동 ↔ 행정동 해상도

실거래가 API는 **법정동**(`umdNm`) 기준이라 행정동에 바로 붙지 않습니다.
서울 행정동 상당수가 법정동명에 번호를 붙인 형태(법정동 구로동 → 행정동
구로1~5동)라, 번호를 벗겨 매칭합니다. 실측 결과 **427개 동 중 344개(81%)가
직접 매칭**되고(아파트 실거래 반영 전 338개/79%였습니다), 나머지 83개는
자치구 중앙값으로 대체되며 화면에 "표본 부족"으로 표시됩니다.

같은 법정동에 속한 행정동들은 같은 월세 값을 갖습니다(삼성1동·삼성2동 → 법정동
삼성동). 이건 원 데이터의 해상도 한계이지 버그가 아닙니다.

### OSM POI 커버리지

실측 결과 서울 편의점 7,132개(실제 약 9,000개의 **79%**), 음식점 42,797개입니다.
절대 개수는 실제보다 적지만 모든 지표를 동 간 **백분위**로 환산하므로 상대
비교에는 문제가 없습니다. 다만 매핑 활동이 활발한 지역(홍대·이태원 등)이 과대
대표될 수 있다는 편향은 남습니다.

## API 키 설정

키 없이도 앱은 동작합니다. 다만 가격 축이 비고(전 동 50점), 지오코딩이 지하철역
이름 검색으로만 동작합니다.

### 1. 국토교통부 실거래가 — 환산월세

[공공데이터포털](https://www.data.go.kr/)에서 아래 세 API를 활용신청합니다.

- 국토교통부_단독/다가구 전월세 실거래가 자료
- 국토교통부_오피스텔 전월세 실거래가 자료
- 국토교통부_아파트 전월세 실거래가 자료

> 승인에 최대 24시간이 걸릴 수 있습니다.

**인증키는 "Decoding" 값을 쓰세요.** 포털은 인증키를 두 형태로 주는데,
`%2B`·`%3D` 가 들어간 Encoding 값을 넣으면 스크립트가 다시 URL 인코딩해서
이중 인코딩이 되고 전부 인증에 실패합니다.

### 2. Kakao Local — 자유 주소·장소 검색

[Kakao Developers](https://developers.kakao.com/)에서 앱 생성 → REST API 키.
월 300만 호출 무료이며 **회사명·학교명 키워드 검색**을 지원합니다
("삼성전자 서초사옥", "서울대학교").

**키 발급만으로는 안 되고 서비스를 켜야 합니다.** 내 애플리케이션 → 제품 설정 →
**카카오맵 → 활성화 설정 ON**. 안 켜면 이런 응답이 옵니다.

```json
{ "errorType": "NotAuthorizedError",
  "message": "App(...) disabled OPEN_MAP_AND_LOCAL service." }
```

키가 없거나 결과가 비면 Worker가 **지하철역 이름 검색으로 폴백**합니다.

### 적용

```bash
# 파이프라인 — .env 파일에 넣으면 스크립트가 읽습니다 (.gitignore 로 제외됨)
cp .env.example .env      # DATA_GO_KR_KEY 를 채우세요
npm run data:metrics && npm run data:score

# Worker — 절대 코드나 설정 파일에 넣지 마세요
npx wrangler secret put KAKAO_REST_KEY
```

`3-metrics.mjs` 는 실거래가를 **동시 요청 2개 + 요청 간 120ms + 지수 백오프
재시도**로 받습니다. 동시 요청 6개로 돌렸더니 약 110건째부터 600건 끝까지 전부
속도 제한에 걸렸습니다(당시 2개 엔드포인트 기준). 지금은 25개 자치구 × 12개월
× 3개 엔드포인트(단독/다가구·오피스텔·아파트) = 900요청이며 실측 약 2분 30초
걸립니다(실패 0건 기준 — API 활용신청이 아직 안 된 엔드포인트가 섞이면
재시도 백오프 때문에 훨씬 오래 걸립니다. `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`
가 그 신호입니다).

## 배포

```bash
# 1) KV 네임스페이스 생성 → 출력된 id를 wrangler.jsonc 에 반영
npx wrangler kv namespace create ONEDAY_KV

# 2) 지오코딩 키 등록
npx wrangler secret put KAKAO_REST_KEY

# 3) 배포
npm run cf:deploy

# 4) 데이터 스냅샷을 KV에 업로드 (이후 데이터 갱신은 이 명령만 실행)
npm run data:seed
```

`/api/data` 는 KV에 스냅샷이 있으면 그걸, 없으면 정적 자산을 서빙합니다(응답
헤더 `X-Oneday-Source` 로 확인). 덕분에 **데이터만 갱신할 때는 프론트를 다시
빌드·배포할 필요가 없습니다.**

Worker 이름(`wrangler.jsonc` 의 `name`)이 곧 workers.dev 주소가 됩니다. 주소에서
계정 식별자를 빼려면 Cloudflare 대시보드 → Workers & Pages → Subdomain 에서
계정 서브도메인을 바꾸면 되고, Worker 쪽은 아무것도 건드릴 필요가 없습니다.

### 배경지도 교체 (선택)

기본값은 CARTO 무료 베이스맵으로 키가 필요 없습니다. 한국어 라벨 품질을 올리려면
[VWorld](https://www.vworld.kr/dev/v4api.do) 인증키를 발급받아 도메인을 등록하고

## 구조

```
src/
  lib/
    dijkstra.ts      다중 출발점 최단경로 (이진 힙) + 경로 복원용 prev
    commute.ts       좌표 → 동별 통근시간, 선택된 동의 경로 복원
    score.ts         가중합 + 상대 컷 등급화 (등급 컷 점수도 함께 반환)
    explain.ts       분포 통계 · 요약 문장 · 계산 과정 — "왜 이 등급인지"
    subwayLines.ts   노선 색 + 노선도 GeoJSON 생성
    shareUrl.ts      화면 상태 ↔ URL 직렬화
    geo.ts           haversine, 최근접역 탐색
    constants.ts     통근 모델 상수 (수정 시 테스트 필수)
  components/
    MapView.tsx      MapLibre — 지오메트리 고정 + feature-state 로 등급만 갱신
    DongDetail.tsx   요약 · 통근 경로 · 접이식 계산 과정
    DestinationSearch.tsx / TopPicks.tsx
worker/
  index.ts           지오코딩 프록시(키 은닉) + 데이터 스냅샷 서빙
scripts/
  1-boundaries.mjs → 2-subway.mjs → 3-metrics.mjs → 4-score.mjs → 5-seed-kv.mjs
```

지도 레이어는 아래에서 위로 이렇게 쌓입니다. 지하철은 **등급 아이콘 아래**에
깝니다 — 주인공은 등급이고 지하철은 그걸 설명하는 배경이라, 역 점이 등급
아이콘을 가리면 주 기능이 손상됩니다.

```
dong-fill → dong-outline → subway-line → subway-hit → subway-station
→ dong-icon → dong-label → route-line → subway-label → dest-marker
```

`subway-hit` 은 투명한 두꺼운 선입니다. 실제 노선은 줌 10에서 1.2px 라 커서로
맞히는 게 사실상 불가능해서, hover 판정만 여기서 받습니다.

테마를 바꾸면 배경지도 스타일을 통째로 교체하는데 **MapLibre 는 setStyle 시
커스텀 소스·레이어를 보존하지 않습니다.** 위 레이어 10개와 소스 6개가 전부
사라지므로 `installLayers()` 로 다시 설치하고, `feature-state` 도 함께 날아가므로
`styleEpoch` 카운터로 상태 반영 effect 들을 재실행시킵니다.

각 파이프라인 스크립트는 **자체 검증을 내장**하고 있으며 실패 시 종료 코드 1을
반환합니다. 예를 들어 총면적이 서울 실면적(605.2 km²)과 30km² 이상 차이 나면
투영 설정 오류로 보고 중단하고, 알려진 환승역(대림 2↔7 등)이 끊겨 있으면 역명
정규화 오류로 보고 중단합니다.

## 알려진 한계

- **CCTV 밀도 미반영** — 원 데이터셋이 폐기됐고 대안이 없습니다(위 참고)
- **5대범죄 해상도** — 경찰서 단위 공개 데이터의 한계로 자치구 단위입니다.
  같은 자치구의 동들은 값이 전부 같습니다
- **월세 해상도** — 같은 법정동의 행정동들은 같은 값을 갖습니다 (자치구
  중앙값으로 대체되는 동 개수는 위 "법정동 ↔ 행정동 해상도" 참고)
- **버스는 정류장 밀도만 봅니다** — "정류장이 많다"를 재는 것이지 "노선이
  다양하다"를 재지 않습니다. 한 노선만 여러 번 서는 동네도 높게 나옵니다.
  노선 다양성까지 보려면 정류장→노선 매핑(서울 1,005개 노선)이 필요합니다
- **역간 소요시간** — 전 구간 추정치이며 실측이 아닙니다 (위 검증표 참고)
- **환승 도보시간** — OSM에 정보가 없어 상수 2분을 씁니다 (실제 1~10분)
- **급행 미반영** — 9호선 급행, 1호선 급행 등은 제외하고 완행 기준입니다
- **노선도·경로선은 역 좌표를 직선으로 이은 것**이지 실제 선로 모양이 아닙니다.
  통근 경로를 점선으로 그리는 것도 그래서입니다
- **OSM POI 편향** — 매핑 활동이 활발한 지역이 과대 대표될 수 있습니다

## 등급 표기에 대해

특정 동네를 공개적으로 "Bad" 로 규정하는 일입니다. 다음을 항상 지킵니다.

1. 등급 옆에 **근거가 되는 실제 수치를 함께 노출**합니다 (유흥업소 44.7개/km² 등)
2. "공공·공개 데이터로 계산한 서울 내 **상대 평가**이며 특정 지역에 대한
   가치판단이 아닙니다" 면책 문구를 상시 표시합니다
3. 데이터 기준일과 출처를 명시합니다
