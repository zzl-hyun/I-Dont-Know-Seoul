# Oneday — 상경자를 위한 자취 구역 추천 지도

회사나 학교를 검색하면, **통근 가능한 서울 동네들이 평판 등급으로 칠해진 지도**를 보여줍니다.

- 서울 **427개 행정동**을 Best / Normal / Bad 로 등급화
- 목적지 기준 **통근시간**을 지하철 그래프로 직접 계산 (외부 길찾기 API 호출 0회)
- **치안 / 가격 / 생활편의** 가중치를 사용자가 직접 조절 → 즉시 재계산

---

## 빠른 시작

```bash
npm install

# 1) 행정동 경계 (전국 34MB → 서울만 추출)
curl -L "https://raw.githubusercontent.com/vuski/admdongkor/master/ver20260701/HangJeongDong_ver20260701.geojson" \
  -o data/raw/hangjeongdong_20260701.geojson
npm run data:boundaries

# 2) 지하철 그래프 (OpenStreetMap, 키 불필요)
npm run data:subway

# 3) 동별 원지표 (OSM POI는 키 불필요 — 아래 "API 키" 참고)
npm run data:metrics

# 4) 정규화 + 등급 + 앱 번들
npm run data:score

# 5) 실행
npm run cf:dev        # Worker + 정적자산 통합 (실환경에 가까움) → http://localhost:8787
npm test              # 통근시간 정확도 회귀 테스트
```

`data/raw/` 는 캐시입니다. 다시 받으려면 해당 파일을 지우고 스크립트를 재실행하세요.

## 설계에서 가장 중요한 결정

### 통근시간을 외부 API 없이 계산한다

목적지 하나당 427개 동의 통근시간이 필요합니다. 길찾기 API를 쓰면 요청당 427콜이라,
ODsay 무료 티어(1,000콜/일)로는 **하루 2명**밖에 못 씁니다.

대신 **지하철 그래프를 직접 만들어 브라우저에서 Dijkstra를 돌립니다.**

```
목적지 좌표
  → 반경 1.5km 내 지하철역 + 도보시간
  → 다중 출발점 Dijkstra (758노드 / 1,822엣지, 1ms 미만)
  → 역별 최단 도달시간
  → 각 행정동: min(동중심→인근역 도보 + 그 역 도달시간)
```

외부 API 호출이 **0회**라 사용량 제한도 요금도 없고, 슬라이더를 드래그해도
네트워크 왕복 없이 즉시 반응합니다.

### 노드는 "역"이 아니라 "(역, 노선)" 쌍

강남역은 2호선 노드와 신분당선 노드로 나뉘고 그 사이를 환승 엣지가 잇습니다.
이렇게 해야 환승 비용이 경로 탐색에 자연스럽게 반영됩니다.

### 역간 소요시간 = 정차 페널티 + 거리 / 순항속도

노선별 "표정속도"를 하나씩 찍는 방식은 역간거리가 짧은 노선(6호선)과 긴 노선
(GTX)을 동시에 맞출 수 없습니다. 표정속도 자체가 역간거리에 종속된 값이기 때문입니다.
물리적으로 분해하면 상수 두 개로 경전철부터 GTX까지 전부 설명됩니다.

검증 (`src/lib/commute.test.ts`):

| 구간 | 모델 | 실제 |
|---|---|---|
| 2호선 순환 일주 (43역 48.8km) | 87.5분 | 87분 |
| 1호선 서울역–인천 (27역) | 62분 | 약 60분 |
| 6호선 응암–봉화산 (38역) | 70분 | 약 75분 |
| 신분당 강남–정자 (6역) | 18분 | 약 16분 |
| 우이신설 전 구간 (13역) | 25분 | 약 24분 |

### 점수는 백분위, 등급은 상대 컷

각 원지표를 서울 427개 동 내 **백분위(0~100)** 로 바꿉니다. 평균/표준편차나
min-max 정규화는 강남 월세 같은 이상치 하나에 전체 분포가 끌려갑니다.

축 점수를 백분위로 저장해두면 종합 점수는 클라이언트에서 **427회 곱셈**이면 되므로,
가중치 슬라이더를 사실상 공짜로 제공할 수 있습니다.

등급은 **서울 전체 분포 기준 상대 컷**(상위 30% / 중간 40% / 하위 30%)입니다.
절대 컷을 쓰면 가중치를 바꾸는 순간 분포가 통째로 이동해 대부분이 한 등급으로 몰립니다.

### CCTV 밀도를 쓰지 않는 이유

원래 치안 축에 넣으려던 서울 열린데이터광장 "안심이 CCTV 연계 현황"(OA-20923)은
**2026-02-10 자로 폐기**됐다("안심주소에 IP 노출로 국정원 지적"). 현재 API는
ERROR-500 을 반환한다.

대안으로 OSM `man_made=surveillance` 를 검토했으나 서울 875개로, 실제 공공 CCTV
약 8만대의 1% 수준이다. 이걸 밀도 지표로 쓰면 지역 간 치안 차이가 아니라 지역 간
매핑 활동 차이를 재게 된다. 그래서 넣지 않았다.

결과적으로 **치안 축은 유흥업소 밀도 하나로만 계산된다.** 새 출처가 생기면
`scripts/3-metrics.mjs` 의 `counts.get(code).cctv` 를 채우고 `cctvOk` 를 켜면 된다.

### 법정동 ↔ 행정동 해상도

실거래가 API는 **법정동**(`umdNm`) 기준이라 행정동에 바로 붙지 않는다.
서울 행정동 상당수가 법정동명에 번호를 붙인 형태(법정동 구로동 → 행정동
구로1~5동)라, 번호를 벗겨 매칭한다. 실측 결과 **427개 동 중 338개(79%)가
직접 매칭**되고, 나머지 89개는 자치구 중앙값으로 대체되며 UI에 "표본 부족"으로
표시된다.

같은 법정동에 속한 행정동들은 같은 월세 값을 갖는다(삼성1동·삼성2동 → 법정동
삼성동). 이건 원 데이터의 해상도 한계이지 버그가 아니다.

### 왜 지하철 데이터를 OSM에서 받는가

국내 공개 데이터셋(서울교통공사 역간거리 등)은 1~8호선만 다루거나 수년째 갱신이
멈춰 있어서 **신림선(2022)·우이신설선(2017)·신분당선 연장이 빠집니다.**
그러면 관악구·강북구가 통째로 "역 없음"이 되어 자취 추천이 망가집니다.
OSM은 노선 릴레이션에 정차 순서가 들어있고 신설 노선이 즉시 반영됩니다.

### OSM POI 커버리지

실측 결과 서울 편의점 7,132개(실제 약 9,000개의 **79%**), 음식점 42,797개입니다.
절대 개수는 실제보다 적지만 모든 지표를 동 간 **백분위**로 환산하므로 상대 비교에는
문제가 없습니다. 다만 매핑 활동이 활발한 지역(홍대·이태원 등)이 과대 대표될 수
있다는 편향은 남습니다.

## API 키 설정

키 없이도 앱은 동작합니다. 다만 가격 축이 비고(전 동 50점), 지오코딩이
지하철역 이름 검색으로만 동작합니다.

### 1. 국토교통부 실거래가 — 원룸 환산월세

[공공데이터포털](https://www.data.go.kr/)에서 아래 두 API 활용신청:
- 국토교통부_단독/다가구 전월세 실거래가 자료
- 국토교통부_오피스텔 전월세 실거래가 자료

> 승인에 최대 24시간이 걸릴 수 있습니다.

**주의 — 인증키는 "Decoding" 값을 쓸 것.** 포털은 인증키를 두 형태로 주는데,
`%2B`·`%3D` 가 들어간 Encoding 값을 넣으면 스크립트가 다시 URL 인코딩해서
이중 인코딩이 되고 전부 인증에 실패한다.

### 2. Kakao Local — 자유 주소·장소 검색

[Kakao Developers](https://developers.kakao.com/)에서 앱 생성 → REST API 키.
월 300만 호출 무료이며 **회사명·학교명 키워드 검색**을 지원합니다
("삼성전자 서초사옥", "서울대학교").

**키 발급만으로는 안 되고 서비스를 켜야 합니다.** 내 애플리케이션 → 제품 설정 →
**카카오맵 → 활성화 설정 ON**. 안 켜면 이런 응답이 옵니다:

```
{"errorType":"NotAuthorizedError",
 "message":"App(...) disabled OPEN_MAP_AND_LOCAL service."}
```

키가 없거나 결과가 비면 Worker가 **지하철역 이름 검색으로 폴백**합니다.

### 적용

```bash
# 파이프라인 — .env 파일에 넣으면 스크립트가 읽는다 (.gitignore 로 제외됨)
echo 'DATA_GO_KR_KEY=<Decoding 인증키>' > .env
npm run data:metrics && npm run data:score

# Worker — 절대 코드/설정에 넣지 말 것
npx wrangler secret put KAKAO_REST_KEY
```

`3-metrics.mjs` 는 실거래가를 **동시 요청 2개 + 요청 간 120ms + 지수 백오프
재시도**로 받는다. 동시 요청 6개로 돌렸더니 약 110건째부터 600건 끝까지 전부
속도 제한에 걸렸다. 25개 자치구 × 12개월 × 2개 엔드포인트 = 600요청이며
몇 분 걸린다.

## 배포

```bash
# 1) KV 네임스페이스 생성 → 출력된 id를 wrangler.jsonc 에 반영
npx wrangler kv namespace create ONEDAY_KV

# 2) 지오코딩 키 등록
npx wrangler secret put KAKAO_REST_KEY

# 3) 배포
npm run cf:deploy

# 4) 데이터 스냅샷을 KV에 올린다 (이후 데이터 갱신은 이 명령만 실행)
npm run data:seed
```

`/api/data` 는 KV에 스냅샷이 있으면 그걸, 없으면 정적 자산을 서빙합니다
(응답 헤더 `X-Oneday-Source` 로 확인 가능). 덕분에 **데이터만 갱신할 때는
프론트를 다시 빌드·배포할 필요가 없습니다.**

### 배경지도 교체 (선택)

기본값은 CARTO 무료 베이스맵으로 키가 필요 없습니다. 한국어 라벨 품질을 올리려면
[VWorld](https://www.vworld.kr/dev/v4api.do) 인증키를 발급받아 도메인을 등록하고
`src/components/MapView.tsx` 의 `BASE_STYLE` 을 교체하세요.

## 구조

```
src/
  lib/
    dijkstra.ts    다중 출발점 최단경로 (이진 힙)
    commute.ts     좌표 → 동별 통근시간
    score.ts       가중합 + 상대 컷 등급화
    geo.ts         haversine, 최근접역 탐색
    constants.ts   통근 모델 상수 (수정 시 테스트 필수)
  components/
    MapView.tsx    MapLibre — 지오메트리 고정 + feature-state 로 등급만 갱신
worker/
  index.ts         지오코딩 프록시(키 은닉) + 데이터 스냅샷 서빙
scripts/
  1-boundaries.mjs → 2-subway.mjs → 3-metrics.mjs → 4-score.mjs → 5-seed-kv.mjs
```

각 파이프라인 스크립트는 **자체 검증을 내장**하고 있으며 실패 시 종료 코드 1을
반환합니다. 예: 총면적이 서울 실면적(605.2 km²)과 30km² 이상 차이 나면 투영
설정 오류로 보고 중단, 알려진 환승역(대림 2↔7 등)이 끊겨 있으면 역명 정규화
오류로 보고 중단.

## 알려진 한계

- **치안 지표가 유흥업소 밀도 하나뿐** — CCTV 데이터셋이 폐기됐고, 5대범죄는
  경찰서 단위라 자치구 해상도가 한계여서 아직 넣지 않았다
- **월세 해상도** — 같은 법정동의 행정동들은 같은 값을 갖는다 (89개 동은 자치구 중앙값)
- **환승 도보시간** — OSM에 정보가 없어 상수 2분 사용 (실제 1~10분)
- **역간 소요시간** — 전 구간 추정치이며 실측이 아님 (위 검증표 참고)
- **급행 미반영** — 9호선 급행, 1호선 급행 등은 제외 (완행 기준)
- **OSM POI 편향** — 매핑 활동이 활발한 지역이 과대 대표될 수 있음

## 등급 표기에 대해

특정 동네를 공개적으로 "Bad" 로 규정하는 일입니다. 다음을 항상 지킵니다.

1. 등급 옆에 **근거가 되는 실제 수치를 함께 노출** (유흥업소 44.7개/km² 등)
2. "공공·공개 데이터로 계산한 서울 내 **상대 평가**이며 특정 지역에 대한
   가치판단이 아닙니다" 면책 문구 상시 표시
3. 데이터 기준일과 출처 명시
